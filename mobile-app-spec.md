# Специфікація: Android-додаток для вивчення англійської (базовий прототип)

Версія: 2.0 (базовий мінімум) · Тип: технічна специфікація прототипу

---

## 1. Мета

Нативний Android-додаток з мінімальним набором функцій:

- авторизація через Google (той самий Firebase-проєкт, що й веб);
- показ уроків поточного користувача (тих, що адмін створив для нього через веб);
- перегляд тексту уроку;
- демо голосової обгортки: озвучення тексту (TTS) і розпізнавання голосу (STT) — фундамент під майбутні голосові фічі.

> Структура уроків не продумується зараз. Урок — це просто текст, прив'язаний до користувача через `ownerUid`.

### Поза обсягом

- Створення/редагування уроків (тільки через веб).
- Повноцінний голосовий діалог з ШІ (закладається на майбутнє).
- iOS (лише Android).
- Офлайн-кеш, нотифікації, складна синхронізація.

---

## 2. Технологічний стек

| Шар | Технологія |
|-----|-----------|
| Мова / UI | Kotlin + Jetpack Compose |
| Авторизація | Firebase Auth (Google) + Credential Manager |
| Дані | Firebase Firestore (Android SDK) |
| Голос (синтез) | Android `TextToSpeech` (on-device) |
| Голос (розпізнавання) | Android `SpeechRecognizer` (on-device, де доступно) |

> Вибір нативного Kotlin: голос — центральна майбутня фіча, прямий доступ до системних STT/TTS стабільніший за мости React Native; iOS не потрібен.

> Офлайн-можливості STT залежать від версії Android і пристрою — звірити з актуальною документацією перед фіналізацією голосу.

---

## 3. Спільний бекенд із вебом

Мобільний не має власного бекенду. Використовує ту саму інфраструктуру:

- той самий Firebase-проєкт (Auth + Firestore);
- ту саму базу: `allowedUsers`, `lessons`;
- одну авторизацію: один Google-акаунт -> один `uid` на обох платформах;
- ті самі Firestore Security Rules.

Контент створюється лише через веб; мобільний працює **тільки на читання**.

---

## 4. Доступ і безпека

- Доступ лише для тих, чий email є у `allowedUsers` (через Firestore Rules).
- Недозволений користувач бачить екран «Доступ не надано».
- Для Google-входу на Android треба зареєструвати **SHA-1 / SHA-256** відбитки (debug і release) у Firebase Console — разове налаштування, без нього логін не працює.

---

## 5. Отримання уроків

Рекомендований шлях для прототипу — прямий Firestore:

1. Прочитати колекцію `lessons`, де `ownerUid == currentUser.uid`.
2. Security Rules гарантують, що користувач читає лише свої уроки.

Альтернатива: `GET /api/my-lessons` веба з заголовком `Authorization: Bearer <token>` (логіка на сервері). Для базового прототипу простіше працювати напряму з Firestore.

---

## 6. Екрани

| Екран | Призначення |
|-------|-------------|
| Login | Кнопка «Увійти через Google» |
| AccessDenied | Якщо користувача немає в `allowedUsers` |
| LessonList | Список своїх уроків |
| LessonDetail | Текст уроку + «Озвучити» (TTS) + «Сказати» (STT-демо) |

---

## 7. Голосова обгортка (демо)

### TTS — озвучення
- Ініціалізувати `TextToSpeech` з `Locale.ENGLISH`.
- Кнопка «Озвучити» зачитує текст уроку.
- Звільняти ресурси (`shutdown`) при виході.

### STT — розпізнавання (демо)
- Запросити дозвіл `RECORD_AUDIO` у рантаймі.
- `SpeechRecognizer` англійською, за можливості офлайн.
- Кнопка «Сказати»: користувач говорить, додаток показує розпізнаний текст.

### Замітка на майбутнє
Голосовий діалог = on-device STT -> хмара (OpenAI) -> on-device TTS. «Мозок» діалогу завжди в хмарі. Запит до OpenAI має йти через серверний ендпоінт веба, щоб не світити ключ у застосунку.

## 8. Дозволи (Manifest)

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

`RECORD_AUDIO` запитується у рантаймі перед першим STT.

---

## 9. Конфігурація проєкту

- `google-services.json` з Firebase Console у модулі `app`.
- Залежності: Firebase Auth, Firestore, Credential Manager + Google ID, Jetpack Compose.
- Зареєструвати SHA-1/SHA-256 (debug і release) у Firebase Console.

---

## 10. Ключові потоки

### Вхід
1. «Увійти через Google» -> Credential Manager -> Firebase сесія + `uid`.
2. Перевірка наявності у `allowedUsers`.
3. Дозволений -> LessonList; ні -> AccessDenied.

### Перегляд уроку та голос
1. У LessonList обрати урок.
2. LessonDetail показує текст.
3. «Озвучити» -> TTS читає текст.
4. «Сказати» -> STT розпізнає мовлення, показує результат.

---

## 11. Критерії приймання

- [ ] Вхід через Google працює зі спільним Firebase-проєктом.
- [ ] Один Google-акаунт дає той самий `uid`, що й на вебі.
- [ ] Недозволений бачить екран «Доступ не надано».
- [ ] Користувач бачить свої уроки, створені через веб.
- [ ] Відкриття уроку показує його текст.
- [ ] TTS озвучує текст англійською.
- [ ] STT розпізнає коротку фразу й показує текст.
- [ ] Жодних секретних ключів у застосунку.

---

## 12. Залежності від веб-частини

- Уроки створюються через веб-адмінку — без неї нема що показувати.
- Дозволені користувачі заводяться через веб / Firestore.
- Спільні Firestore Rules мають бути опубліковані (див. веб-спеку, розділ 5).

---

## 13. Подальші кроки (після прототипу)

- Вправи з аудіювання на основі тексту уроку.
- Голосовий діалог з ШІ: STT -> OpenAI (через серверний ендпоінт) -> TTS.
- Перемикач системний/хмарний TTS для природнішої вимови.
